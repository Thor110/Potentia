# The reader fuzzed (6 November 2026)

Edward chose it from the list of what is left (item 3). Valid `.sieve` files were changed and
installed by a build with AddressSanitizer and UndefinedBehaviorSanitizer (`-fsanitize=address,
undefined`, RelWithDebInfo, its own build folder and its own `_deps`), and every crash, hang or
sanitizer report kept. The fuzzer is `tools/fuzz/fuzz_reader.py`.

- **What was changed:** half and more of the cases changed the listing as the text the reader
  parses (numbers set to edges such as 0, 2^31, 2^32 + 1 and 2^64 - 1; ways replaced by others,
  every recipe among them; paths made hostile: `../x`, `C:\x`, `con.txt`, 300 characters; lines
  deleted, doubled, swapped, or spliced from another seed); the rest changed the raw bytes (bits
  flipped, edge bytes, cut short, bytes put in or taken out).
- **Seeds:** 142 `.sieve` files under 1.5 MB that install as they are within 20 s under the
  sanitizers: the CI's (step 11's fixtures, every version and recipe it makes) and the day's
  benchmark outputs. Each case's time limit is three times its seed's (at least 30 s).
- **Runs:** two. The first (45 minutes, 102 seeds) was stopped by its time limit before it wrote its
  counts; its findings were the two kinds below that are the LZMA SDK's, and slow docs seeds taken
  for hangs (the docs seed takes 48.5 s clean under the sanitizers on a busy machine; the release
  build refuses each changed one in under 8 s), which led to the per-seed limits. The second ran
  for 90 minutes on three workers: **45,283 cases**, 1,264 installed (the change was harmless),
  44,011 refused with a message, **8 reported**.

## What was reported, and what it is

| Report | Where | What it is |
| :--- | :--- | :--- |
| Misaligned store and load (UBSan) | third_party/lzma: LzmaEnc.c, Bra86.c | The LZMA SDK's own unaligned 32-bit accesses, on purpose on x86 and ARM64. Suppressed (`tools/fuzz/ubsan.supp`). |
| Shift by 32 of a 32-bit value (UBSan), 1 case | preflate's `ArithmeticDecoder::decodeBits` (support/arithmetic_coder.h:114), from a damaged deflate difference | Undefined in C++; on x86-64 and ARM64 the shift wraps to 0 and gives a wrong number, which the install refuses ("a run of chunks whose data is not their lengths": the release build, nothing written). In pinned third-party code that Sieve builds unchanged, so not changed here: the one-line fix for Edward to decide on is `bits >= 32 ? 0 : ...` in that function (by a patch step in CMake). Suppressed in the fuzzer meanwhile. *Taken 7 November 2026, in a safer form: that line alone would have left a step of 0 to divide by, so a step of 0 returns 0 too (CMakeLists.txt); the suppression is gone.* |
| Allocation over 2 GiB (ASan), 7 cases | `Model2`'s history (mix.cpp:424), a file's output reserved (locate.cpp:731) | A listing changed to declare a file of 2.3 to 4 GiB, so that size is set aside for it. The installer already refuses, before making anything, instructions whose declared files pass half the memory available (6.6 GiB here), so these are within its bound; ASan's own cap on one allocation (2 GiB) is lower. Not changed. |

No crash, no read or write out of bounds, no hang and no leak was found in Sieve's own code.
