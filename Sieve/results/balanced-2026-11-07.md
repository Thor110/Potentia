# Size, Balanced and Decoding speed (7 November 2026)

Edward: "We should add a middle ground option, IE Balance Size and Decoding speed. That way we can
funnel one set of compression methods one way, one the other way and the rest down the middle";
"measure the three settings first, then build it"; "Balanced should probably be the default".

No new format: each setting chooses among the ways v33 has, and any reader reads what each makes.
Every item packed with Optimise Search (the File Locator's default), installed by `sieve install`,
one at a time on this machine (4 cores), one run each.

## Where it is

**Defaults: Balanced in the File Locator and Create .sieve; Size on the command line**, unless
`--priority` says otherwise.


- The File Locator: one button in place of Prioritise Decoding Speed's box, going round Size,
  Balanced and Decoding speed (P), Balanced unless changed; `[locator] priority` (an older settings
  file's `prioritise_decoding = 1` read as Decoding speed); the hallway's `--priority`. Create .sieve
  from the right-click menu takes the hallway's setting.
- The command line: `--priority size|balanced|speed`, its own Size where none is given, so its
  figures and the CI's stay as they were; `--prioritise-decoding` is speed.
