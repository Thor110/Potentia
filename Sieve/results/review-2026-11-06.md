# Code review of 6 November 2026 (since 963d70a, the review of 4 November)

Two reviewers read the changes since the last review: one the packer, reader and oracle (the
GIF route, v34's version chains, the installer program's blocks, the vault's threads, the
comparisons), one the programs (sieve-view's GIF playing, the thumbnail handler, sieve-install,
the File Locator, the context menu's scripts, the release script). Each finding was traced from a
real input before it was kept, and checked again here before it was fixed.

## Fixed

| Where | What | Fixed so |
| :--- | :--- | :--- |
| locate.cpp `unpack_dictionaries` | a listed file's size (up to ten digits) set aside before it was checked against what the block holds: a damaged installer program could ask for 10 GB | checked first; and a name Windows cannot hold (CON, aux.txt) refused there too |
| pack.cpp `carried_dictionaries_block` | could write a block the reader refuses (over 256 files, a name over 128 bytes, over 256 MiB) | the writer keeps to the reader's limits, and says why where it carries none |
| vault.cpp, a picture's frames | a thread each core per animated picture, inside files already checked on threads; a thread that would not start, or a hash that threw, ended the program | at most 4, a thread that cannot start leaves its share to the others, and a failure is carried back as before |
| vault.cpp, frames kept for the viewer | kept whatever their size, and a .sieve opened at its last picture held the first's while decoding the last | kept only within half the viewer's memory budget; let go first when the last is shown |
| gif_lzw.cpp `gif_open` | every frame's indices held apart, then copied: twice the indices at once | decoded onto the end of one vector |
| pack.cpp / sieve_ref.py, the `gif` recipe | the C++ reader took "+255" (sscanf), the oracle Unicode digits (isdigit) | both take digits alone, no leading zero |
| picture_source.cpp `make_pixels` | a GIF whose blocks count more frames than decode was decoded again on every call; a refusal's reason kept after the frames were made | the frames made are the count; the reason cleared when made again |
| installer_main.cpp | a dropped installer program's own dictionaries were not used | used, as for one named or attached |
| installer_main.cpp | the dictionaries a program carries let go before the installer at exit | declared before it |
| locate.cpp `offered_folder` | read as written (Desktop\Foo) though checked with / for \ | read as checked |
| file_locator.cpp | a folder ending in a separator offered "Documents/" (an empty name) | named by its last folder |
| view_main.cpp | `--thumbnail 0` opened the window; `<stdexcept>` included through another header | refused with a message; included |

## Looked at and left

- **The RAR warning twice** (File Locator): the second is for a packing made again because the
  settings changed, so it is a new packing's warning.
- **The older recipes' numbers** (jbr, stb, skr ...) are read by sscanf as the `gif` recipe was:
  the same leniency, in frozen versions; left, noted.
- **A GIF of very many frames**, checked by the vault on installing: every frame is decoded to be
  checked, within the per-frame limit but not a count of frames; it was so before today, and a
  limit there is a safety choice (refuse, or check fewer), so it is put to Edward rather than made.
