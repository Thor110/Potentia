Title : The Sieve of Potentia - Dynamic Modular State Space Compression Engine

Body :
For a number of years now I have been conceptualising a compression engine which I have named 'The Sieve of Potentia' and have finally been building it out over the past few months.

	Compression

The system utilises various compression methods for comparative analysis throughout the encoding process, coupled with a final pass of custom search methods that improve the results, as well as breaking data down into chunks to test against various methods.

It includes a file delta scanner which optimises files when they contain much of the same data.

Example : WoWRevived which is a restoration project of mine for an old video game (Jeff Wayne's 'The War of the Worlds' the 1998 RTS PC game) contains two nearly identical files that it swaps between, one containing the regular minimaps and the other containing higher resolution minimaps.

The two files are scanned, the 98.7% similarity is noted and the ~160mb file which otherwise would have been reduced to ~52mbs, becomes a ~2mb script that lifts the data from the near identical file as it is decoded.

Alongside that it checks file hashes and trims exact duplicates to be a single file that gets unpacked accordingly.

As well as pattern matching that turns repeating byte patterns into instruction sets for procedurally regenerating those blocks of the data.

It also checks file contents for base64 representations of files to ensure they get compressed properly. ( ie : base64 jpeg embedded in html )

Then there is an auditable logger that details the exact formulae or recipe used for the files it compresses.

All compression done by this application is lossless and the data is reproduced byte for byte, except when using the permanent option for repacking compressed formats: there the content is kept exactly (a JPEG’s picture, a PNG’s pixels, an archive’s files) but the container is repacked for a smaller result, so that file’s own bytes differ.

Files can be optimised for decoding speed or filesize, as well as a number of other parameters that allow for more exhaustive searches if desired.

	Statistics

So far, most tests are outperforming 7zip and repacking JPEG and PNG files smaller than they started.

Sieve beats brotli on folders and large files, as well as small web pages since the latest v33 manifest.

PROOF.md - https://github.com/Thor110/Potentia/blob/main/Proof/PROOF.md

The written proof describes the basic functionality of the state space which theoretically allows for maximum compression under perfect circumstances.

Those circumstances would be finding the perfect balance through a filter applied to the state space which would shift the file you are searching for to an exact integer interval rotation within the relevant state space.

A filter made for one file costs about as much to describe as it saves.

No method can shrink every file, so the counting argument holds.

The point of the state space is that for any given file a filter exists that places it at a short address; degrees.sieve noted in and alongside PROOF.md shows this for 3,960 'real' files.

Finding that filter for an arbitrary file is the intractable part, though I hold out hope to find a real file this way one day...

	AI Training Harness

The application also includes an AI training harness for training AI models locally.

My reasoning for this is that Potentia was the title for my thesis on AI alignment which can be found on the github pages and in the main readme.

You can read part of the thesis here : https://github.com/Thor110/Potentia/tree/main#why-it-exists

In short, just as with human beings we can not guarantee alignment, neither can we with AI systems, that is to say it is intractable but trackable with recorded ordering of training data.

Comparable to allowing an AI model to walk the Library of Babel to train on the data as it goes, inevitably, its probability distribution becomes chaotic, messy and requires constant upkeep to prevent model collapse, while making it impossible for models alone to overcome token weight conflicts without heuristics or harnesses.

Think of a model walking the Library of Babel as it trains, what it becomes depends on which books it reads and in what order, and that route can’t be read back out of the model afterwards.

The data and the order in which it is ingested fundamentally alter the course of alignment and the model’s probability distribution, recording the route is what makes it possible to check, rerun and compare.

Traditional AI training records model weights and checkpoints, but subtle hardware-level variations, thread scheduling differences, and floating-point round-off drift mean that reproducing a model bit-for-bit from scratch is notoriously difficult.

By enforcing strict integer-only arithmetic throughout the training loop—where every activation, gradient, and weight update is explicitly bounded, shifted, and quantized, Sieve ensures absolute, deterministic bit-reproducibility across any machine architecture. ( Windows / Mac / Linux tested )

Floating point is used in models for its range and speed, what it costs is reproducibility.

Every number is a signed 64 bit integer, so values are a fixed point, this means it is bounded by max/min values.

Initial analysis of Sieve trained models shows that no value ever hits the min or max on the shipped models, however these models are tiny so precision and scale still needs further analysis. On a larger test model a small share did.

Probabilities are fixed point too, so a model can give a byte exactly 0%, and sometimes that byte comes next.

No one can say with absolute certainty that something has no chance of following something else, depending on the pre-requisite context of course.

For example : ‘waffle’ may be very unlikely after ‘quantised’, but that doesn’t stop me typing ‘quantised waffle’.

So a model used to compress needs a minimum chance for every byte, this is planned for the next training version.

	The Sieve AI Model

Trained on just The Universal Library 'Kurd Laßwitz’s 1904 short story Die Universalbibliothek' which amongst other influences, inspired the Library of Babel by Jorge Luis Borges.

sieve-ai-16432c2a3953.safetensors : 34,072 bytes : 0.462 s to encode to .sieve
sieve-ai-16432c2a3953.safetensors.sieve : 4,180 bytes : 0.042 s to decode from .sieve

An 8192 weight model reduced to fewer bytes than it has weights.

The model is 34,072 bytes as .safetensors, which stores each 4-bit weight as a 32-bit float, reduced to 4,180 bytes as a .sieve, that is the 8,192 weights own 4,096 bytes, plus 84 bytes of name, hash and overhead.

The model isn't capable and it isn't supposed to be, it is just a proof of concept.
